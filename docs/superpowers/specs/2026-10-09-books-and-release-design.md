# 여러 책과 장 공개 설계

목업: https://claude.ai/artifact/6Z78EfRE1EnTdzb5X1QyDb (서재, 장 고르기, 잠긴 장, 처음 열 때 받기, 저장 공간, 미공개 미리 보기, 관리 도구 공개 화면, 흐름)

## 1. 목표와 완료 기준

창세기만 다루던 코드를 성경 66권 어디로든 넓힐 수 있게 하고, 관리자가 장마다 공개한 것만 앱에서 열리게 한다. 공개는 앱 업데이트 없이 앱에 닿는다.

완료 기준:
1. 파이프라인, 관리 도구, 서버, 앱 어디에도 창세기 고정이 없다. 새 책은 66권 목록에 이미 있고, 본문 받기부터 단계를 돌리면 된다.
2. 관리 도구의 공개 화면에서 점검을 통과한 장만 공개할 수 있다. 공개, 다시 공개, 공개 취소가 공개 상태 파일에 남는다.
3. 공개하면 꾸러미와 공개 목록이 만들어지고, 앱은 다음에 목록을 받을 때 그 장을 열고 내려받는다.
4. 미공개 장은 앱에서 잠겨 보이고 열리지 않는다. 미리 보기로 띄운 개발 빌드만 미공개 장을 "미공개" 표시로 연다.
5. 지금까지의 창세기 기록(읽은 장면, 읽던 곳, 계획, 밑줄·메모, 끝까지 푼 퀴즈)이 그대로 이어진다.

## 2. 범위

넣는 것: 66권 목록, 모든 단계의 책 인자, 절 참조에 책, 공개 상태와 점검, 관리 도구 공개 화면, publish 단계(꾸러미, 공개 목록, 미리 보기), 동기화 서버의 콘텐츠 제공, 앱의 목록 받기·잠금·내려받기·저장 공간·기록 이전, 공개된 것만 쓰는 질문하기.

빼는 것: 운영 저장소(S3 호환 저장소와 CDN) 결정과 올리기 명령, 신약 원어 자료, 공개 알림, 여러 책에 걸친 읽기 계획(통독), 웹 목업 변경.

## 3. 단계

단계마다 구현 계획(`docs/superpowers/plans/`)을 따로 쓰고, 작업 브랜치 `feature/books-and-release`에서 커밋한다. 세 단계가 끝나면 main에 합친다(`docs/git-convention.md`).

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 여러 책 기반: 66권 목록과 절 참조(reader-core), 파이프라인·관리 도구·서버의 책 인자, 설정집 참조 이전 | 창세기 동작이 그대로다(장면·퀴즈·음성 파일 이름은 그대로, 앱 묶음은 `bookId`만 더해짐, 설정집 참조에는 책이 붙음). 전체 테스트 통과. 다른 책도 `--book`으로 본문 받기부터 돌 수 있다 |
| 2 | 공개: 공개 상태 파일과 점검, publish 단계(꾸러미, 공개 목록, 미리 보기), 관리 도구 공개 화면, 동기화 서버의 `/content`, 질문하기가 공개 꾸러미를 씀 | 공개한 장만 목록에 오르고, 다시 공개하면 바뀐 파일만 새 이름이 된다 |
| 3 | 앱: 목록 받기, 66권 서재와 잠금, 꾸러미·그림·낭독 내려받기와 저장 공간, 여러 책 읽기와 기록 이전, 미리 보기 빌드, 시작 꾸러미 | Expo 웹에서 공개, 다시 공개, 공개 취소가 앱에 반영된다 |

**1단계 진행 (2026-10-10 완료).** 계획은 `docs/superpowers/plans/2026-10-09-books-and-release-stage1.md`이다. 창세기 결과물은 그대로다(장면·퀴즈·음성 파일 이름, 묶음 내용). 묶음에는 `bookId`만 더해졌다. 원어 낱말은 크티브 대신 크레를 쓰게 하면서 창세기 8:17 하나가 바뀌었다.

만들면서 바꾼 것:
- `build`는 `--book`을 받지 않고 언제나 본문이 있는 모든 책의 묶음을 만든다(앱 콘텐츠 폴더를 비우고 다시 쓰므로).
- 본문은 위키문헌에서 책마다 받는다(`source --book <id> --chapters 1-10`). 요한1서~3서는 쪽 이름이 다르고, 요한계시록은 이어지는 줄을 합친다. 받은 본문은 겹친 장과 장 순서를 검사한다.
- 설정집 인용은 `genesis 2:7`처럼 책 id를 붙여 저장한다(`migrate-canon-refs`로 옮겼다). 책 묶음에는 그 책까지 나온 항목만 넣는다. 그 책의 인용은 책 없이(`2:7`), 앞 책의 인용은 책 이름을 붙여(`창세기 2:7`) 넣고, 뒤 책의 인용은 뺀다. 앱은 앞 책 인용을 0장으로 읽어 이미 만난 것으로 본다. 같은 이름의 앞 책 인물은 아직 가르지 못한다(3단계 Task 1 Step 0).
- 원어는 책마다 만든다. 히브리어(WLC) 절 번호는 OSHB의 `VerseMap.xml`로 개역한글 절 번호에 맞추고, 맞출 수 없는 장(느헤미야 7장, 시편 72편, 아가 6장)은 원어 없이 둔다(구약 929장 중 926장). 크티브 대신 크레를 쓰고, 사전 횟수는 모든 책에서 센다. 신약은 건너뛴다.
- 본문 파일 하나를 읽지 못하면 그 책을 인용한 설정집 항목만 확인하지 못한다. 관리 도구는 그런 책을 목록에 알리고, 다른 책의 화면은 그대로 쓴다.
- 관리 도구는 주소에 책을 넣는다(`/api/books/:book/…`). 설정집 인용은 책 이름으로 보이고 받는다.
- 질문하기는 묶음 폴더의 모든 책 묶음을 읽고 읽고 있는 책의 대목을 앞에 둔다. 묶음 하나라도 잘못되면 질문하기만 끄고 서버는 뜬다.
- 앱은 책 id와 책 이름을 묶음에서 읽는다. 다른 책의 메모와 근거는 3단계 전까지 열지 않는다. 로그인 서버에 닿지 않으면 처리되지 않은 오류 없이 로그아웃 상태로 두고 다시 시도한다.

다른 책의 콘텐츠를 만들기 전에 정할 것:
- 장면 프롬프트의 규칙 1(한 장 4~8장면, 한 장면 한 사건)은 이야기 본문을 전제한다. 율법·성막·시가서·서신서와 아주 짧은 장(시편 117편, 2절)에 맞는 규칙이 필요하다.
- 그림 규칙의 "없어야 하는 것"(해·달·별, 동물, 건물, 연장)은 창세기 1~11장에 맞춘 것이라 책마다 다시 본다.
- 장면 프롬프트에 넣는 설정집의 범위(지금은 승인된 전체).
- 설정집 메모의 "이 장에서는" 같은 표현.

## 4. 책과 절 참조

**66권 목록.** `reader-core`의 `books.ts`에 둔다. 책마다 id, 한국어 이름(개역한글), 구약·신약, 장 수, OSIS 코드(원어 자료 파일 이름, 예: `Gen`), 원어(히브리어, 아람어가 섞인 책, 그리스어)를 적는다. id는 지금 쓰는 `genesis`처럼 영어 소문자다(`exodus` … `revelation`). 장마다 절 수는 목록에 적지 않고 본문에서 센다.

**id와 파일 이름.** 장 번호는 그 책의 장 수 자리수로 채운다. 창세기(50장)는 두 자리라 지금 id와 파일이 그대로고, 시편(150장)은 세 자리다.

| 무엇 | 형식 | 예 |
|---|---|---|
| 장면 | `<책>-<장>-<장면 2자리>` | `genesis-04-03`, `psalms-119-02` |
| 절 낭독 | `<책>-<장>-<절 3자리>.mp3` | `genesis-04-015.mp3` |
| 퀴즈 문제 | `<책>-<장>-q<n>` | `genesis-04-q1` |
| 본문 | `content/source/<책>.json` | |
| 장면 | `content/scenes/<책>-<장>.json` | |
| 퀴즈 | `content/quiz/<책>-<장>.json` | |
| 원어 낱말 | `content/original/<책>.json` | 사전 항목은 `lexicon.json` 하나(번호에 H·G가 붙어 겹치지 않는다) |

**절 참조.** 책을 넘나드는 곳(설정집)의 참조는 `<책> <장>:<절>` 또는 `<책> <장>:<절>-<절>`로 쓴다(`genesis 4:1-5`). 장면·퀴즈처럼 한 장 안의 것은 지금처럼 절 번호만 쓴다. 참조를 읽고 비교하는 함수는 `reader-core`의 `refs.ts` 하나로 모은다. 비교는 (책 순서, 장, 절) 순서다. 인물을 "만났는지"는 읽은 곳과 처음 나오는 곳을 이 순서로 비교한다.

**설정집.** 성경 전체에 하나다(`content/story-bible/`). 항목의 참조에 책을 붙인다. `canon` 단계는 `--book <id> --chapter N`으로 돌고, 모델이 쓴 `장:절` 참조에 책을 붙여 합친다.

**프롬프트.** 장면, 검수, 설정집, 원어 뜻, 퀴즈, 질문하기 프롬프트의 "창세기"는 책 이름으로 바꾼다. 원어 뜻 프롬프트의 "창세기 1~10장"은 "이 앱에 있는 장"으로 바꾼다.

**원어.** 구약은 OSHB(`<OSIS>.xml`, 같은 고정 커밋)와 스트롱 히브리어 사전, 신약은 자료를 정할 때까지 원어 보기를 감춘다.

## 5. 공개 상태와 점검

**공개 상태 파일** `content/releases.json`(커밋한다):

```json
{
  "revision": 13,
  "books": {
    "genesis": {
      "1": { "revision": 2, "publishedAt": "2026-10-09T06:20:00Z", "hash": "3f9c2a1b7d0e" }
    }
  }
}
```

`revision`(맨 위)은 공개 목록 판이고 공개, 다시 공개, 공개 취소마다 하나 오른다. 장의 `revision`은 그 장을 몇 번 공개했는지, `hash`는 공개한 장 꾸러미의 내용 해시다. 공개 취소는 그 장 항목을 지운다.

**점검(필수, 하나라도 빠지면 공개 단추가 꺼진다):**
- 장면 파일이 있고 장면이 모두 사람 승인(`approved`)이다.
- 기본 그림 버전(그림 버전 목록의 마지막)에 장면마다 그림이 있다.
- 장의 모든 절에 낭독이 있다.

**선택(점검에 넣지 않고 승인된 만큼 나간다):** 원어 뜻, 퀴즈(승인된 문제가 셋 이상이면 앱에서 열린다).

**바뀐 것.** 공개 화면은 장 꾸러미를 메모리에서 만들어 해시를 공개 상태 파일과 비교한다. 다르면 "바뀐 것 있음"과 무엇이 바뀌었는지(글, 그림, 낭독, 퀴즈, 원어 뜻)를 보이고 다시 공개 단추를 켠다.

## 6. 꾸러미와 공개 목록(publish 단계)

공개 단추는 공개 상태 파일을 고치고 `publish` 단계를 돌린다. `publish`는 공개 상태 파일과 콘텐츠만 보고 `publish/`(git 제외)를 처음부터 다시 만든다. 같은 내용이면 같은 파일 이름이 나온다.

```
publish/
  catalog.json                        공개 목록
  canon.<해시>.json                   공개된 장에 나오는 승인 설정집 항목
  lexicon.<해시>.json                 공개된 장에 나오는 사전 항목(승인된 한국어 뜻만)
  packs/<책>/<장>.<해시>.json          장 글 꾸러미
  media/<장면 id>.<해시>.jpg           장면 그림(기본 버전만)
  media/<장면 id>.<해시>.mp3           장면 낭독(절 낭독을 이은 것)
  preview/                            미공개 장의 같은 형식(이 PC에서만)
```

해시는 내용의 SHA-256 앞 12자리다. 파일 이름이 내용을 따라가므로 앱은 이름이 바뀐 파일만 받고, 서버는 해시 파일을 오래 캐시해도 된다.

**장 글 꾸러미:** 장 번호, 절(본문), 장면(제목, 해설, 낱말 풀이, 역사 배경, 장소, 인물, 그림·낭독 파일 이름과 길이), 원어 낱말(절마다), 승인된 퀴즈.

**공개 목록:**

```json
{
  "schemaVersion": 1,
  "revision": 13,
  "translation": "개역한글",
  "canon": { "file": "canon.a1b2c3d4e5f6.json", "size": 48211 },
  "lexicon": { "file": "lexicon.0f1e2d3c4b5a.json", "size": 120394 },
  "sources": [],
  "books": {
    "genesis": {
      "1": { "revision": 2, "pack": "packs/genesis/1.3f9c2a1b7d0e.json", "size": 31877, "media": [{ "file": "media/genesis-01-01.9a8b7c6d5e4f.jpg", "size": 158204 }] }
    }
  }
}
```

목록에는 공개된 장만 오른다. 66권과 장 수는 앱이 `reader-core`의 목록으로 안다. `sources`는 지금 묶음의 자료 출처와 같다.

**미리 보기.** `publish`는 장면 파일이 있는 미공개 장도 `preview/`에 같은 형식으로 만든다. `preview/catalog.json`에는 공개된 장과 미리 보기 장이 함께 오르고, 미리 보기 장에는 `"preview": true`와 점검 결과가 붙는다. 운영 저장소에는 `preview/`를 올리지 않는다.

**웹 목업.** `build` 단계는 지금처럼 `app/public/content/genesis.json`을 만든다. 웹 목업은 바꾸지 않는다.

## 7. 콘텐츠 서버

- 개발: 동기화 서버가 `/content/*`를 `publish/`에서 낸다. `catalog.json`은 매번 확인(`no-cache`, ETag), 해시 파일은 오래 캐시(`immutable`). `/content/preview/*`는 `CONTENT_PREVIEW=1`일 때만 낸다.
- 운영: S3 호환 저장소와 CDN에 `publish/`를 올린다(`preview/` 제외). 저장소와 올리기 명령은 서버를 올릴 때 정한다.
- 질문하기: 대목을 공개 목록의 꾸러미에서 만든다. 공개된 장과 공개된 설정집만 근거가 된다. 서버는 시작할 때와 목록 판이 바뀌었을 때 다시 읽는다.

## 8. 앱

**목록.** 앱을 켤 때와 다시 앞으로 올 때 `catalog.json`을 받는다. 받은 목록은 기기에 두고, 연결이 안 되면 마지막 목록을 쓴다.

**시작 꾸러미.** 첫 실행이 인터넷 없이 되도록, 앱을 빌드할 때 `publish/`의 공개 목록과 공개된 창세기 앞 장들의 꾸러미·그림·낭독(합계 상한 30 MB)을 앱에 넣는다. 앱은 시작 꾸러미를 먼저 쓰고 더 새 목록을 받으면 바꾼다.

**내려받기.** 공개된 장의 글 꾸러미와 공용 설정집·사전은 목록을 받으면 저절로 받는다(작다). 그림은 장을 열 때 받고, 설정에 따라 다음 장 그림을 미리 받는다. 낭독은 들을 때 받고, 받는 동안은 서버 주소로 바로 재생한다. "와이파이에서만 받기"가 켜져 있으면 모바일 데이터로는 그림과 낭독을 받지 않는다(글은 받는다). 받은 파일은 `expo-file-system`의 앱 문서 폴더에 파일 이름(해시) 그대로 둔다. 웹(확인용)은 내려받기 없이 서버에서 바로 읽는다.

**잠금.** 서재, 장 고르기, 목차, 검색 결과, 이어 읽기에서 미공개 장은 잠겨 보인다. 잠긴 장을 누르면 "준비 중" 시트가 뜨고, 지금 읽을 수 있는 곳으로 안내한다. 공개 취소된 장을 읽던 중이면 그 책의 마지막 공개 장으로 옮기고, 받아 둔 파일은 지운다(기록은 남긴다).

**저장 공간.** 설정 시트에서 연다. 받아 둔 용량, 책마다 "전부 받아 두기"와 "지우기", "와이파이에서만 받기", "다음 장 그림 미리 받기".

**여러 책 읽기.** 읽기 화면은 지금 책을 들고 연다. 장 고르기는 책의 모든 장을 보이고, 책을 바꾸는 것은 서재에서 한다. 검색, 인물 사전, 가계도, 연표, 지도, 질문하기, 위젯은 공개되고 받은 장만 쓴다.

**기록.** 읽던 곳에 책을 넣는다(책이 없는 지금 기록은 창세기로 읽고, 다음에 저장할 때 책을 넣는다). 읽은 장면, 밑줄·메모, 퀴즈 기록은 이미 책이 들어 있어 그대로다. 계획은 읽고 있는 책을 기준으로 하고 계획 기록에 책을 넣는다. 동기화 서버의 컬렉션은 바꾸지 않는다.

**미리 보기 빌드.** `EXPO_PUBLIC_CONTENT_PREVIEW=1`로 띄운 개발 빌드나 Expo 웹은 `preview/catalog.json`을 받아 미공개 장을 위에 "미공개 미리 보기" 띠를 두고 연다. 그림 버전 바꿔 보기는 미리 보기에서만 보인다(꾸러미에는 기본 버전만 들어간다).

## 9. 관리 도구

- **공개 화면**(목업): 책을 고르면 장마다 점검(필수·선택)과 상태(공개됨·판, 바뀐 것 있음, 점검 미통과, 장면 쓰기 전, 본문 받기 전)를 보인다. 공개, 다시 공개, 공개 취소 단추와 다시 공개 전 바뀐 것 요약이 있다. 단추는 공개 상태 파일을 고친 뒤 `publish` 작업을 돌린다.
- **책 고르기:** 대시보드, 장면, 퀴즈, 원어 뜻, 작업 화면에서 책을 고른다. 작업 폼의 단계는 모두 책을 받는다.
- 공개 상태 파일을 고치는 동안 `publish` 작업이 돌고 있으면 저장을 막는다(409, 원어 뜻·퀴즈 저장과 같은 방식).

## 10. 이전

- **설정집 참조:** 한 번 도는 이전 명령이 책 없는 참조(`2:7`)에 `genesis `를 붙인다. 결과를 커밋한다.
- **파일 이름:** 창세기 장면·퀴즈·음성 이름은 자리수 규칙 그대로라 바뀌지 않는다.
- **앱 기록:** 읽던 곳과 계획 기록에 책이 없으면 창세기로 읽는다.
- **형식:** 꾸러미와 공개 목록은 새 형식(`schemaVersion` 1)이다. 기존 묶음(`genesis.json`)은 웹 목업용으로 남는다. 앱은 3단계에서 묶음 대신 공개 목록과 꾸러미를 읽는다.

## 11. 위험과 대응

- **장 수 많은 책의 id 자리수:** 책마다 자리수 규칙을 시험으로 고정한다(창세기 두 자리, 시편 세 자리).
- **공개 직후 앱에 반영되지 않음:** 목록은 매번 확인하므로, 앱을 다시 열면 반영된다.
- **서버에 옛 해시 파일이 쌓임:** `publish`가 `publish/`를 새로 만들므로 로컬에는 남지 않는다. 운영 저장소는 목록에 없는 파일을 지우는 수명 규칙을 둔다.
- **첫 실행 오프라인:** 시작 꾸러미로 연다.
- **공개 점검이 엄격해 지금 공개할 장이 없음:** 지금 장면은 모델 검수까지만 됐다. 공개하려면 관리 도구에서 장면 승인부터 한다. 개발과 화면 확인은 미리 보기로 한다.
- **신약 원어:** 자료와 이용 조건을 정할 때까지 원어 보기를 감춘다.
