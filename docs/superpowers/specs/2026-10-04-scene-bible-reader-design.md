# 장면으로 읽는 성경 — 목업 설계

- 날짜: 2026-10-04
- 상태: 초안 (검토 전)
- 대상 범위: 창세기 1~10장

## 1. 목표

두 가지를 한 번에 확인하는 목업을 만든다.

1. **읽기 화면**: 화면 위 절반에 그림, 아래 절반에 성경 본문이 있고, 본문을 내려 읽으면 그림이 장면에 맞춰 바뀐다. 지도에서 지금까지 지나온 장소를 볼 수 있고, `?`에서 장면 해설과 역사 배경을 볼 수 있다.
2. **AI 파이프라인**: LLM이 장면 시나리오를 쓰고, 인물·장소·그림체 설정을 기억해 일관되게 유지하고, 결과물을 본문과 대조해 검수한 뒤 그림을 만든다.

### 완료 기준

1. 모바일 폭 브라우저에서 창세기 1~10장을 스크롤하면 장면이 바뀔 때 위 그림이 바뀐다.
2. 지도에 지나온 장소가 순서대로 이어져 보이고 현재 위치가 표시된다.
3. `?`를 누르면 현재 장면의 해설, 낱말 풀이, 역사 배경이 나온다.
4. 명령 하나로 한 장(章)의 장면·검수 결과·그림이 만들어지고, 다시 실행하면 이미 만든 것은 건너뛴다.
5. 모든 장면에 검수 결과(통과 또는 확인 필요, 그 사유)가 기록된다.

## 2. 범위

**포함**

- 읽기 화면, 지도 화면, 해설 시트
- 그림 위 자막(켜고 끄기), 절 단위 음성 낭독과 자동 넘김
- GitHub Pages 배포
- 콘텐츠 파이프라인 전 단계 (본문 준비 → 시나리오 → 설정집 → 글 검수 → 역사 사실 검수 → 인물 기준 이미지 → 장면 그림 → 그림 검수 → 앱용 묶음)
- 창세기 1~10장 콘텐츠

**제외**

- 로그인, 서버, 메모, 알림, 읽기 기록 동기화
- 네이티브 앱 (화면은 나중에 옮길 수 있게 콘텐츠와 분리만 해 둔다)
- 창세기 11장 이후, 다른 번역본
- 검수용 관리 화면 (목업에서는 보고서 파일과 JSON 직접 수정으로 대신한다)

## 3. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 그림이 바뀌는 단위 | 장면 (연속된 구절 1~8개) | 1~10장은 267절이다. 절마다 그리면 267장이고, 장면으로 묶으면 50~60장 정도다. |
| 본문 번역 | 개역한글 (1961) | 저작권 보호기간이 끝났다. 개역개정은 대한성서공회 허가가 필요하다. |
| LLM | OpenAI API | 사용자 결정. |
| 장면 그림 | OpenAI 이미지 API (기본 `gpt-image-2.5-sunburst`, 품질 high, JPEG) | 사용자 결정. 참고 이미지를 입력으로 받을 수 있어 인물 일관성에 쓴다. |
| 화풍 고정 | 사람이 그린 퍼블릭 도메인 수채화의 붓질 조각을 참고 이미지로 넣고, 종이·물감·붓질을 구체적으로 적은 문구를 함께 쓴다 | 모델의 기본 화풍에서 나오는 반복 질감을 줄인다. 그림 전체가 아니라 조각만 넣어 구도가 딸려 오지 않게 한다. |
| 지도 | OpenStreetMap + Leaflet | 사용자 결정. 오픈소스 지도 위에 장소를 표시한다. |
| 낭독 음성 | OpenAI 음성 API (`gpt-4o-mini-tts`), 절마다 mp3 하나 | 사용자 결정. 기기마다 목소리가 달라지지 않게 미리 만들어 둔다. |
| 배포 | GitHub Pages (GitHub Actions) | 사용자 결정. `main`에 푸시하면 자동으로 배포된다. |
| 버튼 등 UI 그래픽 | Higgsfield로 만든 이미지 파일 | 사용자 결정. 파일이 들어오기 전에는 기본 선 아이콘을 쓴다. |
| 목업 형태 | 모바일 웹 (React + Vite + TypeScript) | 가장 빨리 만들고 브라우저로 바로 확인할 수 있다. |
| 서버 | 없음 | 파이프라인이 미리 만든 정적 파일을 앱이 읽는다. |
| 파이프라인 언어 | TypeScript (Node 22) | 앱과 같은 언어로 맞춘다. |

모델 ID는 코드에 고정하지 않고 `.env`의 `OPENAI_TEXT_MODEL`, `OPENAI_IMAGE_MODEL`로 둔다. 글 모델은 구조화 출력과 이미지 입력을 지원하는 모델이어야 한다.

### 표현 기준

검수 단계가 이 기준을 그대로 판정 항목으로 쓴다. 교회나 팀의 입장에 따라 바꿀 수 있도록 `content/story-bible/style.json`에 둔다.

- 하나님은 사람의 모습으로 그리지 않는다. 빛, 구름 등으로 표현한다.
- 에덴의 아담과 하와는 구도와 식물로 가려 노출이 없게 한다.
- 폭력(가인과 아벨, 홍수의 죽음)은 직접 묘사하지 않는다.
- "해석"은 본문에 나오는 낯선 낱말(옛말, 지명, 인명, 물건 이름)의 뜻풀이다. 절 사이에 줄거리를 요약한 해설은 넣지 않는다. 뜻풀이와 배경 설명은 특정 교파의 해석을 담지 않고, 지명·인명처럼 정체가 불확실한 것은 그렇다고 적는다.
- 위치가 불확실한 장소(에덴 등)는 "추정"으로 표시한다.

### 역사 배경 기준

`?`에는 본문 밖의 역사적 사실을 넣는다. 예를 들어 본문이 어떤 인물의 나이를 기록하면, 고고학이 추정하는 당시 사람들의 평균 수명을 함께 적는다.

- 본문의 기록과 역사 연구의 내용을 구분해서 쓴다. 본문이 옳은지 그른지 판정하지 않고 나란히 제시한다.
- 사실마다 근거를 남긴다. 무엇을 바탕으로 한 말인지(고고학 발굴, 고대 문헌 등) 적는다.
- 확실하지 않으면 "추정" 또는 "견해가 갈림"으로 표시한다. 추정을 단정으로 쓰지 않는다.
- 출처로 확인하지 못한 사실은 싣지 않는다.

## 4. 구조

```
chansu-bible-temp/
  app/              읽기 화면 (React + Vite + TypeScript)
  pipeline/         콘텐츠 생성 스크립트 (Node + TypeScript)
  content/          파이프라인의 입출력. 사람이 읽고 고칠 수 있는 JSON과 이미지
    source/           본문 (개역한글)
    story-bible/      설정집: style.json, characters.json, places.json, refs/
    scenes/           장별 장면 파일: genesis-01.json …
    images/           장면 그림. 버전마다 폴더 하나(v1-flare/ 등)와 버전 목록(versions.json)
    audio/            절마다 낭독 음성 (genesis-01-001.mp3)
    review-report.md  검수 요약 (자동 생성)
  docs/
```

세 부분의 경계는 다음과 같다.

- `pipeline`은 `content/`를 읽고 쓴다. 앱 코드를 모른다.
- `app`은 묶음 파일(`app/public/content/`)만 읽는다. 파이프라인 코드를 import하지 않는다.
- 둘 사이의 약속은 묶음 파일의 형식 하나다. 나중에 네이티브 앱으로 가면 `app/`만 새로 만든다.

## 5. 콘텐츠 데이터

### 본문 — `content/source/genesis.json`

```json
{ "book": "창세기", "translation": "개역한글",
  "chapters": [ { "chapter": 1, "verses": [ { "verse": 1, "text": "태초에 하나님이 천지를 창조하시니라" } ] } ] }
```

### 설정집 — `content/story-bible/`

| 파일 | 내용 |
|---|---|
| `style.json` | 그림체 설명, 이미지 프롬프트 앞에 붙는 그림체 문구와 뒤에 붙는 표현 기준 문구, 화풍 참고 이미지 목록과 참고 지시문 |
| `characters.json` | 인물별 `id`, 이름, 나이대, 외형, 복장, 첫 등장 절, 기준 이미지 경로 |
| `places.json` | 장소별 `id`, 이름, 설명, 추정 여부, 위도·경도(`lat`, `lng`) |
| `refs/` | 화풍 참고 이미지(출처는 `style.json`의 `references[].source`), 인물 기준 이미지 |

### 장면 — `content/scenes/genesis-NN.json`

장면 하나의 필드:

| 필드 | 설명 |
|---|---|
| `id` | `genesis-01-02` 형식 |
| `chapter`, `verseStart`, `verseEnd` | 이 장면이 덮는 절 범위 |
| `title` | 장면 제목 |
| `commentary` | 쓰지 않음(`null`). 절 사이의 요약 해설은 넣지 않기로 했다 |
| `explanation` | `?` 시트의 장면 해설 문단들. 줄거리 요약이 아니라 구절을 읽는 데 도움이 되는 설명이다: 표현과 원어의 뜻, 구절의 구조, 다른 구절과의 연결, 당시 독자에게 어떻게 읽혔을지. 학자들 사이에 견해가 갈리는 것은 그렇다고 적는다 |
| `glossary` | 낱말 풀이 목록. 항목마다 `verse`(절), `word`(본문에 그대로 나오는 표현), `meaning`(뜻). `word`가 그 절 본문에 없으면 묶음을 만들 때 오류가 난다 |
| `history` | `?` 시트의 역사 배경 목록. 항목마다 `text`(내용), `basis`(근거 설명), `certainty`(`확실` / `추정` / `견해 갈림`), `sources`(검수 때 확인한 출처 주소) |
| `visual.description` | 그림에 무엇이 보이는지 |
| `visual.shot` | 구도 지시: 거리, 시점, 시간대, 여백. 장면마다 다르게 주어 그림들이 서로 닮지 않게 한다 |
| `visual.characters` | 등장 인물 `id` 목록 |
| `placeId` | 장소 `id`. 장소가 없는 장면은 `null` |
| `image` | 지금 만들고 있는 그림 버전 폴더 안의 파일 이름. 아직 없으면 `null` |
| `review.status` | `draft` → `reviewed` 또는 `flagged` → `approved` |
| `review.text`, `review.facts`, `review.image` | 글·역사 사실·그림 검수의 판정과 지적 사항 목록 |
| `review.attempts` | 재작성 횟수 |

## 6. 파이프라인

각 단계는 `content/`의 파일을 읽고 쓴다. 이미 결과가 있는 장면은 건너뛰고, `--force`를 주면 다시 만든다.

| 순서 | 단계 | 하는 일 | LLM |
|---|---|---|---|
| 0 | `source` | 개역한글 본문을 가져와 절 단위 JSON으로 만든다. 장별 절 수(31, 25, 24, 26, 32, 22, 24, 22, 29, 32)를 검증한다. | 아니오 |
| 1 | `scenario` | 장 본문과 현재 설정집을 넣고, 장면 목록과 새 인물·장소 제안을 받는다. | 예 |
| 2 | 설정집 반영 | 새 인물·장소만 추가한다. 이미 있는 항목은 바꾸지 않는다. | 아니오 |
| 3 | `review-text` | 장면을 본문·설정집·표현 기준과 대조해 판정한다. | 예 (별도 호출) |
| 4 | `review-facts` | 역사 배경의 사실마다 웹 검색으로 대조하고 출처 주소를 기록한다. | 예 (웹 검색) |
| 5 | `refs` | 설정집의 인물마다 기준 이미지를 만든다. | 이미지 |
| 6 | `images` | 글 검수를 통과한 장면만 그린다. 프롬프트는 "그림체 문구 + 인물 설정 + 장면 묘사"로 조립하고, 등장 인물의 기준 이미지를 참고 이미지로 함께 넣는다. 1024×1024로 만든다. | 이미지 |
| 7 | `review-image` | 만든 그림을 장면 묘사·표현 기준과 대조해 판정한다. | 예 (이미지 입력) |
| 8 | `tts` | 절마다 낭독 음성을 만든다. 본문을 그대로 읽으며, 이미 음성이 있는 절은 건너뛴다. | 음성 |
| 9 | `build` | 본문·장면·장소·그림을 앱용 묶음으로 합쳐 `app/public/content/`에 쓴다. `review-report.md`를 만든다. | 아니오 |

### 안전장치

- **본문은 LLM을 거치지 않는다.** 앱에 보이는 성경 본문은 항상 `source`에서 온다. LLM이 만드는 것은 제목·해설·역사 배경·그림 묘사뿐이다.
- **절 범위는 코드로 검증한다.** 한 장의 장면들이 모든 절을 순서대로, 빠짐없이, 겹치지 않게 덮어야 한다. 어기면 그 장의 시나리오를 다시 받는다.
- **작성과 검수를 분리한다.** 검수는 작성 때의 대화 내용을 보지 못하는 별도 호출이고, 지시문도 따로 둔다.
- **설정집은 덮어쓰지 않는다.** 한 번 정해진 인물의 외형은 LLM이 바꿀 수 없다. 바꾸려면 사람이 파일을 고친다.
- **지도 좌표는 사람이 넣는다.** LLM은 장소 이름과 설명만 제안한다. 좌표가 없는 장소는 지도에 그리지 않고 보고서에 누락으로 적는다.

### 검수 판정 항목

글 검수:

1. 해설이 줄거리 요약에 그치지 않고 읽기에 도움이 되는 설명인가. 본문에 없는 사건을 지어내거나 특정 교파의 교리를 단정하지 않는가. 견해가 갈리는 것을 그렇다고 적었는가
1-1. 낱말 풀이의 낱말이 그 절 본문에 그대로 있고 뜻이 사전적으로 맞는가
2. 그림 묘사가 본문과 어긋나는가 (인물 수, 순서, 사물)
3. 그림 묘사가 설정집과 어긋나는가 (외형, 복장, 장소)
4. 표현 기준을 어기는가

역사 사실 검수:

1. 사실이 출처로 확인되는가
2. 확실성 표시가 출처의 내용과 맞는가 (추정을 단정으로 쓰지 않았는가)
3. 본문의 기록과 구분해서 썼고, 본문을 판정하지 않는가

출처로 확인하지 못한 항목은 지운다. 고쳐 써야 하는 항목이 남으면 그 장면을 `flagged`로 둔다.

그림 검수:

1. 그림이 장면 묘사와 맞는가
2. 표현 기준을 어기는가
3. 그림 안에 글자나 깨진 형상이 있는가

불합격이면 지적 사항을 넣어 다시 만든다. 2회 다시 만들어도 불합격이면 `flagged`로 두고 다음 장면으로 넘어간다. 사람이 확인해 고친 뒤 JSON의 `status`를 `approved`로 바꾼다.

목업에서는 `flagged` 장면도 묶음에 넣고, 앱에서 "확인 필요" 표시를 붙여 보여준다. 실제 서비스에서는 `approved`만 내보내야 한다.

### 명령

```
npm run pipeline -- source
npm run pipeline -- scenario --chapter 1
npm run pipeline -- review-text --chapter 1
npm run pipeline -- review-facts --chapter 1
npm run pipeline -- refs
npm run pipeline -- images --chapter 1
npm run pipeline -- review-image --chapter 1
npm run pipeline -- build
npm run pipeline -- all --chapter 1
```

- `--force`: 이미 있는 결과를 다시 만든다.
- `--dry-run`: API를 부르지 않고 보낼 프롬프트만 출력한다.

API 키는 `.env`의 `OPENAI_API_KEY`로 읽는다. `.env`는 커밋하지 않고 `.env.example`만 커밋한다.

## 7. 앱

### 읽기 화면

- 위 절반: 현재 장면의 그림. 왼쪽 위에 지도 버튼과 `?` 버튼, 왼쪽 아래에 장면 제목.
- 아래 절반: 본문이 세로로 스크롤된다. 맨 위에 "창세기 N장" 선택기(1~10장)가 있다.
- 본문은 장면 단위로 묶여 있다. 풀이가 있는 낱말은 점선 밑줄로 표시되고, 누르면 아래에 뜻 카드가 뜬다. 다른 낱말을 누르면 바뀌고, 닫기를 누르면 사라진다.
- 아래 절반의 위쪽 기준선을 지난 장면이 현재 장면이 된다. 현재 장면이 바뀌면 위 그림이 0.3초 동안 겹쳐지며 바뀐다.
- 그림이 아직 없는 장면은 장면 제목만 있는 빈 그림 칸을 보여준다.
- 장의 끝에 "다음 장" 버튼이 있다.
- 마지막으로 읽던 위치를 기기에 저장해 다시 열면 이어서 보여준다.

### 지도 화면

- OpenStreetMap 지도 위에 장소를 점으로 찍는다. 지도에 적힌 지명은 오늘날의 현지 표기다.
- 창세기 1장 첫 장면부터 현재 장면까지의 장소를 순서대로 실선으로 잇는다. 같은 장소가 연달아 나오면 하나로 합친다.
- 현재 위치를 강조하고, 다음 장소 하나만 점선으로 보여준다.
- 장소가 없는 장면(창조 등)에서는 직전 위치를 유지한다. 아직 장소가 하나도 없으면 "아직 지도에 표시할 장소가 없어요"를 보여준다.
- 추정 위치는 이름 옆에 "추정"을 붙인다.

### 장소 전환 안내 (2026-10-07 추가)

장면이 바뀌면서 장소가 달라지면 여정 지도 화면(위의 "지도 화면")이 저절로 열린다. 지도는 이전 장면의 장소(지도에 있을 때)에서 출발해 새 장소로 날아가고, 아래 정보에는 "새 장소: 이전 → 새 장소"가 뜬다. 잠시 머문 뒤 저절로 닫힌다. 처음에는 그림 위에 작은 지도를 따로 띄웠는데, 사용자가 "그 지도(여정 지도)로 오버레이가 뜨고 사라져야" 한다고 해서 바꿨다.

- 여는 조건: 새 장면의 장소가 지도에 있고(위도·경도가 있음) 이전 장면의 장소와 다를 때. 처음 열 때, 장소가 없어졌을 때(장소 → 없음), 해설 시트를 보고 있을 때는 열지 않는다.
- 시간: 출발 위치 0.5초 → 날아가기 1.6초 → 머물기 2.2초 → 사라지기 0.4초. 움직임 줄이기 설정이면 날아가지 않고 바로 옮기며 효과 없이 2.6초 머문다.
- 그동안 지도를 만지거나 키를 누르면 저절로 닫히지 않고 보통의 지도 화면처럼 남는다. 닫기 버튼과 Esc는 평소와 같다. 저절로 열릴 때는 닫기 버튼으로 포커스를 옮기지 않는다.
- 낭독으로 장면이 넘어갈 때도 똑같이 열린다. 열려 있는 동안 또 장소가 바뀌면 새 장소로 다시 날아간다.
- 로직은 `placeChange(places, 이전 장소 id, 새 장소 id)`와 `flashTiming(움직임 줄이기)` 순수 함수로 두고 시험한다.

### 해설 시트

- `?`를 누르면 아래에서 올라온다. 현재 장면의 해설 문단, 낱말 풀이(절별), 역사 배경 순서로 보여준다.
- 그 아래에 역사 배경을 보여준다. 항목마다 내용, 근거, 확실성 표시가 붙는다.

### 자막과 낭독

- 현재 위치는 절 단위로 잡는다. 현재 절이 속한 장면이 현재 장면이다.
- 자막을 켜면 현재 절의 본문이 그림 위에 자막으로 보인다. 켜고 끄는 버튼이 있고, 선택은 기기에 저장된다.
- 재생 버튼을 누르면 현재 절부터 음성으로 읽는다. 한 절이 끝나면 다음 절로 넘어가고, 장의 끝에서는 다음 장으로 넘어간다. 본문은 현재 절을 따라 스크롤된다.
- 읽는 동안 "AI 음성"이라고 표시한다. OpenAI 사용 정책상 AI가 만든 목소리임을 알려야 한다.
- 음성이 없는 절에서는 재생할 수 없다.

### 그림 버전 (시험용)

- 그림 생성 방식을 비교하기 위해 그림을 버전별로 보관한다. `content/images/versions.json`에 버전 목록(id, 이름, 만든 방식)이 있고, 버전마다 `content/images/<id>/` 폴더가 있다.
- `images` 명령은 목록의 마지막 버전 폴더에 그린다. 새 방식을 시험하려면 목록에 버전을 추가하고 `--force`로 다시 그린다.
- 앱에서는 그림 위의 버튼을 누를 때마다 다음 버전의 그림으로 바뀐다. 기본은 마지막 버전이고, 선택은 기기에 저장된다. 그 버전에 그림이 없는 장면은 빈 그림 칸으로 나온다.

## 8. 오류 처리

- API 호출 실패는 간격을 늘려 가며 3회 다시 시도한다. 그래도 실패하면 그 장면을 건너뛰고 끝에 실패 목록을 출력한다.
- LLM 출력은 스키마로 검증한다. 형식이 틀리면 다시 받는다.
- 단계가 중간에 멈춰도 그때까지 만든 결과는 파일에 남아 있어, 다시 실행하면 이어서 진행한다.
- 앱은 묶음 파일을 못 읽으면 "콘텐츠를 불러오지 못했어요"와 다시 시도 버튼을 보여준다.

## 9. 테스트

- 파이프라인: 절 범위 검증, 설정집 반영(기존 항목 보존), 프롬프트 조립, 묶음 생성을 단위 테스트한다. LLM 호출은 가짜 응답으로 대체한다.
- 앱: 현재 장면 계산과 지도 경로 계산을 단위 테스트한다.
- 화면은 모바일 폭 브라우저에서 직접 확인한다.

## 10. 진행 단계

1. **뼈대**: 폴더 구조, 본문 데이터, 그림 없이 본문만으로 동작하는 읽기 화면.
2. **1장 관통**: 창세기 1장으로 파이프라인 전 단계를 연결한다. 장당 비용과 소요 시간을 잰다.
3. **인물 일관성 확인**: 창세기 2~4장(아담, 하와, 가인, 아벨)으로 기준 이미지 방식이 통하는지 본다. 1장에는 반복해 나오는 인물이 없어 이 확인이 안 된다.
4. **확장**: 5~10장, 지도 좌표, Higgsfield UI 그래픽 반영.

## 11. 위험

- **인물 일관성**: 기준 이미지를 넣어도 장면마다 얼굴이나 복장이 달라질 수 있다. 3단계에서 안 되면 방식을 다시 정한다.
- **족보 장(5장, 10장)**: 그릴 사건이 적다. 장면 수를 줄이고 계보나 민족 분포 그림으로 채운다.
- **비용**: 그림 50~60장에 재생성과 검수 호출이 더해진다. 2단계에서 잰 값으로 전체 비용을 추정한 뒤 확장한다.
- **역사 사실의 정확성**: LLM은 그럴듯한 수치를 지어낼 수 있다. 출처 대조를 거쳐도 틀릴 수 있으므로, 역사 배경은 공개 전에 사람이 확인해야 한다.
- **옛 말투**: 개역한글은 읽기 어렵다. 해설과 낱말 풀이로 보완한다.
- **본문 출처**: 가져온 개역한글 본문에 오탈자가 있을 수 있다. 절 수 검증만으로는 못 잡으므로, 1장은 사람이 한 번 대조한다.
